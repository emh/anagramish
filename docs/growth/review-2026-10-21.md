## Puzzle audit

The shipped date algorithm, dictionary, and hard-mode rules validate these routes (also legal in normal mode):

- October 15: REVEL → REVUE → CURVE → TRUCE → CHUTE → BUTCH.
- October 18: GOODY → GODLY → DOILY → DAILY → VALID → ALIVE.
- October 20: DONUT → TONED → TREND → DETER → DEFER → FEVER.

Normal completions were 3/20, 5/14, and 1/7 respectively. These are solvable puzzles; finding a route is different from validating one. This audit does not establish whether vocabulary, rules, UI, interruptions, or audience mix caused unfinished games. Keep date selection and the dictionary unchanged pending evidence. Automated solving is not human usability testing.

For the next human observation, invite 3–5 people unfamiliar with the game. Give only the homepage and ask them to think aloud, choose whether to use the tutorial, and attempt a puzzle. Record where they hesitate, their understanding of rearrangement and the prefilled end word, tutorial exits, and the point they stop. Do not coach until the observation is over. Ask what they expected next. Recruiting/contacting participants is not part of this change.

## Measurement changes

- Game-start diagnostics: date, daily/practice, normal/hard, browser count, total starts, maximum starts from one browser, and starts restoring saved progress. Existing events support historical reporting. No raw browser IDs are exported.
- The API already deduplicates starts by session ID. Frontend reopens reuse the saved ID. Practice resets/new practice games and hard-mode changes can create new IDs. The October 18 total of 109 starts from 14 players cannot be assigned to those causes from the old aggregate export. Use the new `start_activity` rows to separate activity types and concentration; concentration alone is not evidence of a bot or bug.
- First tutorial attempt per browser: wait a full 24 hours; count completion of the same attempt and recorded game play/completion after it within that window. Replays do not rescue an abandoned first attempt. Report how many eligible learners had previously played. This uses historical start/completion events, is observational, and includes daily and practice games.
- Lesson-start, lesson-complete, and explicit-exit events are idempotent per attempt and lesson. These are prospective. Exiting after finishing a lesson can count in both columns. Missing completion is not proof of abandonment. Closing the tab is not an explicit exit; offline telemetry is best effort and uses server receipt time.
- Existing day-seven retention is return on exactly day seven, not any return within seven days.
